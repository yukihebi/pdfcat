# pdfcat CI Design

## Goal

Add a minimal GitHub Actions CI to enforce formatting, linting,
tests, and a release build on every change, plus a vulnerability
scan and an automated dependency-update flow.

## File layout

```
.github/
├── workflows/
│   ├── ci.yml         # fmt, clippy, test, build (parallel jobs)
│   └── audit.yml      # cargo audit (PR/push + weekly cron)
└── dependabot.yml     # weekly updates for cargo + github-actions
```

Three new files. No existing files are modified except `README.md`
(adds one badge line).

## `ci.yml`

### Triggers

- `push` to `main`
- `pull_request` (any base branch)

### Common setup

- `runs-on: ubuntu-latest`
- `dtolnay/rust-toolchain@stable` (with `rustfmt` / `clippy`
  components on the jobs that need them)
- `Swatinem/rust-cache@v2` on every job
- Env vars:
  - `CARGO_TERM_COLOR: always`
  - `RUSTFLAGS: -D warnings` (promote warnings to errors uniformly)

### Jobs (run in parallel)

| Job | Command | Extra toolchain component |
|---|---|---|
| `fmt` | `cargo fmt --all -- --check` | `rustfmt` |
| `clippy` | `cargo clippy --all-targets --all-features -- -D warnings` | `clippy` |
| `test` | `cargo test --all-features` | — |
| `build` | `cargo build --release` | — |

### Expected duration

First run (cold cache): ~5 min, dominated by the `lopdf` build.
Subsequent runs: 1–3 min per job, in parallel.

## `audit.yml`

### Triggers

- `push` to `main`, only when `Cargo.lock` changes
- `pull_request`, only when `Cargo.lock` changes
- `schedule`: weekly cron (`0 0 * * 1`, Monday 00:00 UTC) to catch
  CVEs disclosed after the code last changed
- `workflow_dispatch` (manual run)

### Job

- `runs-on: ubuntu-latest`
- `actions/checkout@v4`
- `rustsec/audit-check@v2` with `token: ${{ secrets.GITHUB_TOKEN }}`
  (action prints a summary and can open issues for new advisories)

### Policy

- Fail the job on actual vulnerabilities.
- Do **not** treat informational advisories (warnings, withdrawn,
  unmaintained) as failures, so a retracted advisory does not block
  unrelated work. This is the default `audit-check` behavior.

## `dependabot.yml`

```yaml
version: 2
updates:
  - package-ecosystem: cargo
    directory: "/"
    schedule:
      interval: weekly
    open-pull-requests-limit: 5
  - package-ecosystem: github-actions
    directory: "/"
    schedule:
      interval: weekly
    open-pull-requests-limit: 5
```

- `cargo`: tracks `Cargo.toml` (currently `lopdf`, `thiserror`).
- `github-actions`: tracks the actions used in workflows above.
- PR limit 5 to avoid PR flooding on a personal tool.

## README badge

Prepend one line near the top of `README.md`:

```markdown
[![CI](https://github.com/yukihebi/pdfcat/actions/workflows/ci.yml/badge.svg)](https://github.com/yukihebi/pdfcat/actions/workflows/ci.yml)
```

Audit badge is intentionally omitted (informational advisories would
make it noisy).

## Out of scope

- OS matrix (Ubuntu only)
- Toolchain matrix (stable only; no beta, no pinned MSRV)
- Release artifact upload (build is verified, not published)
- Coverage measurement (tarpaulin, llvm-cov)
- Caching beyond `Swatinem/rust-cache`

These can be added later if the project grows beyond a personal tool.

## Local reproduction

Developers can run the exact same checks locally:

```sh
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo build --release
```
